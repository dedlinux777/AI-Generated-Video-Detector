# AI-Generated Video and Audio Detector

A research and educational application with exactly two input modes: multimodal
video detection and standalone audio detection.

## Detection Workflows

- **Video Detection:** OpenCV samples full frames and resizes them to the
  committed EfficientNet graph's 224x224 NHWC input contract. FFmpeg extracts the original audio stream, which is
  converted to mono, resampled to 16 kHz, and length-normalized for RawNet.
  When audio is available, visual and audio opinions are combined with
  Dempster-Shafer evidence fusion. Videos without a readable audio stream
  produce a clearly labelled visual-only prediction.
- **Audio Detection:** Uploaded or microphone-recorded audio is decoded,
  converted to mono, resampled to 16 kHz, and passed as a raw waveform to
  RawNet. No spectrogram image or visual branch is used.

The committed `checkpoints/model.pth` was audited and contains only legacy
`rgb_encoder` and `spec_encoder` weights. It is not an ETMC checkpoint and is
never used as one. ETMC inference requires a separately produced
`checkpoints/etmc_model_best.pt` containing `state_dict`, `architecture_config`,
`class_mapping`, and `architecture` metadata; loading is strict and fails
clearly when any part is missing or incompatible. No ETMC performance is
reported until that real checkpoint is supplied.

Reported opinions use canonical class order `REAL, FAKE`. The legacy visual
branch maps `(0, 1)` to that order and the legacy RawNet branch maps `(1, 0)`;
this must be re-verified for any newly trained checkpoint.

Predictions are research results, not proof of authenticity.

ETMC inference uses the trained visual, acoustic, pseudo-view, and
Dempster-Shafer fusion heads directly. The standalone audio mode loads only the
acoustic ETMC branch and does not initialize or execute the visual branch.

TFRecord generation uses the explicit persisted training mapping
`real=0, fake=1`; ETMC training checkpoints save this mapping alongside the
model state. The committed legacy encoder checkpoint remains separate and does
not contain ETMC heads or fusion parameters.

## Requirements

- Python 3.10 or newer.
- CPU or CUDA-capable PyTorch, depending on your hardware.
- Git LFS to download the trained checkpoint files when they are stored as LFS objects.

## Installation

```powershell
git clone https://github.com/dedlinux777/AI-Generated-Video-Detector.git
cd AI-Generated-Video-Detector

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

If Git LFS is installed, fetch the model files with:

```powershell
git lfs install
git lfs pull
```

The application expects these files in `checkpoints/`:

- `model.pth`
- `efficientnet.onnx`

For trained ETMC inference, also provide `etmc_model_best.pt` generated by
`main.py`. The legacy files above are preserved for the legacy encoder tooling
and cannot substitute for this checkpoint.

## Run

```powershell
python app.py
```

Open the local Gradio URL shown in the terminal. The application contains **Video Detection** and **Audio Detection** tabs. Audio accepts uploads and microphone recordings.

## Supported Inputs

- **Video:** MP4, AVI, MOV, MKV, WebM, and FLV, subject to the installed OpenCV and Gradio decoders.
- **Audio:** WAV, MP3, FLAC, OGG, AAC, M4A, and other formats that `soundfile` or `torchaudio` can decode.

## Static Frontend and Legacy API

`frontendhtml/` is a separate static frontend; `python app.py` launches the Gradio application and does not serve these files. The static page posts video/audio uploads to the legacy Flask API configured in `frontendhtml/script.js`. That backend forwards requests to its configured Hugging Face Space and reports service failures instead of returning demo predictions. Configure the API URL for the environment where the static page and backend are deployed.

## Project Layout

| Path | Purpose |
| --- | --- |
| `app.py` | Gradio video/audio application entry point |
| `inference_2.py` | Two-stream video and standalone RawNet inference |
| `models/evidential.py` | Dirichlet opinions, uncertainty, and DS fusion |
| `models/` | Visual encoder, RawNet, and ETMC model components |
| `checkpoints/` | Trained model weights and EfficientNet ONNX model |
| `audios/`, `videos/` | Sample media |
| `frontendhtml/` | Independent static frontend |
| `gradioapibackend.py` | Legacy Flask API used by the static frontend |

## Notes

- `static_ffmpeg` configures bundled FFmpeg binaries for media decoding; video
  inference also requires an FFmpeg executable available to the process.
- `tests/test_evidential.py` covers opinion normalization, conflict stability,
  and high-uncertainty fusion. Numerical tests do not establish model accuracy.
- Do not upload private or sensitive media when using a shared deployment.
